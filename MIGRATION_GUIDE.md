# Data Migration Guide

## 🔄 Migrating from localStorage to Database

This guide explains how to migrate your existing data from browser localStorage to the database.

---

## 📋 What Gets Migrated

### Feedback Data
- All user feedback and suggestions
- Page names, dates, user info
- Feedback details and timestamps

### Use Case Registry Data
- Use case entries
- KPI tables
- Data requirements
- Risk assessments
- Stakeholder information
- Project milestones

---

## 🚀 Migration Methods

### Method 1: Automatic Migration (Recommended)

The app will automatically detect localStorage data and offer to migrate it.

**Steps:**
1. Start both servers (backend and frontend)
2. Open the application
3. If data is detected, you'll see a migration prompt
4. Click "Migrate Data"
5. Wait for migration to complete
6. Done! Your data is now in the database

### Method 2: Manual Migration Page

Access the dedicated migration page:

**Steps:**
1. Start both servers
2. Navigate to: http://localhost:3000/migrate
3. Click "Start Migration"
4. Follow the on-screen instructions
5. Migration complete!

### Method 3: Browser Console (Advanced)

For developers who want manual control:

**Steps:**

1. Open browser console (F12)
2. Run the migration:

```javascript
import { migrateFromLocalStorage } from './utils/migrate';

// Run migration with progress updates
await migrateFromLocalStorage((progress) => {
  console.log(progress.message, progress.progress + '%');
});
```

## 📊 Migration Process

### What Happens During Migration

1. **Detection Phase**
   - Checks for data in localStorage
   - Counts feedback items and use cases
   - Verifies if migration was already done

2. **Backup Phase**
   - Creates backup of localStorage data
   - Stores backup in localStorage under 'localStorageBackup'

3. **Migration Phase**
   - Migrates feedback items one by one
   - Migrates use cases with all related data
   - Reports progress in real-time

4. **Completion Phase**
   - Marks migration as completed
   - Keeps original data as backup
   - Shows migration results

### Data Transformation

**Feedback:**
```javascript
// localStorage format
{
  id: 1737849600000,
  pageName: "Executive Overview",
  date: "2026-01-25",
  name: "John Doe",
  email: "john@example.com",
  details: "Great dashboard!",
  timestamp: "2026-01-25T10:30:00.000Z"
}

// Database format (same structure)
{
  id: 1,  // Auto-generated by database
  page_name: "Executive Overview",
  submission_date: "2026-01-25",
  user_name: "John Doe",
  user_email: "john@example.com",
  details: "Great dashboard!",
  timestamp: "2026-01-25T10:30:00.000Z",
  created_at: "2026-01-25T10:30:00.000Z"
}
```

## 🔒 Safety Features

### 1. Non-Destructive Migration
- Original data remains in localStorage
- Migration only copies data
- No data is deleted during migration

### 2. Automatic Backup
- Creates backup before migration
- Backup stored in localStorage
- Can be restored if needed

### 3. Error Handling
- Continues even if some items fail
- Reports errors at the end
- Allows retry

### 4. Idempotency
- Won't migrate twice
- Checks if migration already completed
- Safe to run multiple times

## 🛠️ Troubleshooting

### Migration Fails to Start

**Problem:** "Server is not responding"

**Solution:**
```bash
# Check if server is running
curl http://localhost:3001/api/health

# If not, start server
cd server
npm start
```

### Some Items Failed to Migrate

**Problem:** Migration completed with errors

**Solution:**
1. Check browser console for error details
2. Verify data format in localStorage
3. Try migrating failed items manually
4. Contact support if issues persist

### Migration Stuck at 0%

**Problem:** Progress bar not moving

**Solution:**
1. Check browser console for errors
2. Verify API connection
3. Refresh page and try again
4. Check server logs for errors

### Want to Re-run Migration

**Problem:** Need to migrate again

**Solution:**
```javascript
// Clear migration flag
localStorage.removeItem('migrationCompleted');

// Run migration again
// (Use migration page or console method)
```

## 🔄 Rollback

### Restore from Backup

If you need to restore your original localStorage data:

**Browser Console:**
```javascript
import { restoreFromBackup } from './utils/migrate';

const result = restoreFromBackup();
console.log(result);
// Refresh page
```

**Manual Restore:**
```javascript
// Get backup
const backup = JSON.parse(localStorage.getItem('localStorageBackup'));

// Restore feedback
localStorage.setItem('userFeedback', JSON.stringify(backup.feedback));

// Restore use cases
localStorage.setItem('useCases', JSON.stringify(backup.useCases));

// Clear migration flag
localStorage.removeItem('migrationCompleted');
```

## 🧹 Cleanup

### After Successful Migration

Once you've verified the migration was successful, you can optionally clean up:

**Keep Backup (Recommended):**
```javascript
// Do nothing - backup remains in localStorage
```

**Remove Backup:**
```javascript
import { clearLocalStorageBackup } from './utils/migrate';
clearLocalStorageBackup();
```

**Manual Cleanup:**
```javascript
// Remove original data
localStorage.removeItem('userFeedback');
localStorage.removeItem('useCases');

// Remove backup
localStorage.removeItem('localStorageBackup');

// Keep migration flag
// localStorage.removeItem('migrationCompleted');
```

## 📞 Support

### Common Questions

**Q: Will my data be lost?**  
A: No, original data remains in localStorage as backup.

**Q: Can I migrate multiple times?**  
A: Yes, but it will skip if already completed. Clear the flag to re-run.

**Q: What if migration fails?**  
A: Your original data is safe. You can retry or restore from backup.

**Q: How do I know it worked?**  
A: Check the User Suggestions tab or query the database directly.

**Q: Can I undo the migration?**  
A: Yes, use the restore from backup function.
